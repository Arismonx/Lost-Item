## 1. ออกจากระบบแล้ว `/broadcast` ยังโชว์ปุ่มเพิ่มประกาศ ✅

- **อาการ:** ล็อกอินเป็น officer/admin เปิด `/broadcast` แล้วออกจากระบบ กลับมาหน้า `/broadcast` ยังเห็นปุ่ม "+ เพิ่มประชาสัมพันธ์" เหมือนยังล็อกอินอยู่
- **สาเหตุ:** Next.js (เปิด `cacheComponents`) จำสถานะ React ของหน้าที่เคยเปิดไว้ หน้า `/broadcast` เก็บ `user` ไว้ใน state ที่โหลดครั้งเดียวตอนเปิดหน้า และ `router.refresh()` ไม่ล้าง state ของหน้าเดิม
- **ผลกระทบ:** เฉพาะการแสดงผล ปุ่มกดแล้วเพิ่มประกาศไม่ได้จริง เพราะ `POST /api/broadcasts` ตรวจสิทธิ์ที่ backend ซ้ำ (`requireRole`)
- **วิธีแก้:** `/logout`, `/login`, `/register` เปลี่ยนจาก `router.push/replace + refresh` เป็นโหลดหน้าใหม่ทั้งหมด (`window.location`) ทุกหน้าจึงดึงข้อมูลผู้ใช้ใหม่
- **ไฟล์:** `frontend/src/app/logout/page.js`, `login/page.js`, `register/page.js`
- **ทดสอบ:** ผู้ใช้ทดสอบในเบราว์เซอร์แล้วใช้งานได้

## 2. ประชาสัมพันธ์ยังแสดงของที่ส่งคืนแล้ว ✅

- **อาการ:** ของที่ส่งมอบคืนแล้ว (หรือมีข้อโต้แย้ง) ประกาศยังค้างที่หน้า `/broadcast` และหน้าแรก
- **สาเหตุ:** `GET /api/broadcasts` ดึงทุกแถวจากตาราง `broadcasts` โดยไม่ดูสถานะของหายที่ผูกอยู่ (`item_id`) และตอนยืนยันส่งมอบก็ไม่ได้ลบประกาศ
- **วิธีแก้:** `GET /api/broadcasts` join กับ `lost_items` และซ่อนประกาศที่ของมีสถานะ `returned` หรือ `disputed` ประกาศที่เจ้าหน้าที่เขียนเอง (ไม่มี `item_id`) ยังแสดงตามเดิม ข้อมูลในฐานข้อมูลไม่ถูกลบ
- **ไฟล์:** `backend/src/routes/broadcasts.js`
- **ตอนตรวจ:** ในฐานข้อมูลมีประกาศของที่ส่งคืนแล้ว 4 รายการ (ถูกซ่อน) เหลือแสดง 5 รายการ
- **ทดสอบ:** ผู้ใช้ทดสอบในเบราว์เซอร์แล้วใช้งานได้

## 3. ลบประชาสัมพันธ์/ของหายไม่ได้ ✅

- **อาการ:** ประกาศที่พิมพ์ผิดหรือส่งซ้ำแก้ไม่ได้ ต้องลบใน SQL เอง (ไม่ใช่บัคโค้ด แต่เป็นฟีเจอร์ที่ขาด พบตอนตรวจหน้า `/broadcast`)
- **วิธีแก้:**
  - `DELETE /api/broadcasts/:id` (officer, admin) ลบเฉพาะประกาศ
  - `DELETE /api/lost-items/:id` (officer, admin) ลบได้เฉพาะสถานะ `found` เพราะของที่ส่งคืนแล้วมีประวัติการส่งมอบผูกอยู่ (ตอบ 409) ลบประกาศที่ผูกอยู่และไฟล์รูปให้ด้วย ใน transaction เดียวกัน
  - เพิ่มปุ่ม "ลบ" ที่ `/broadcast` และ `/lost-items` พร้อม confirm
- **ไฟล์:** `backend/src/routes/broadcasts.js`, `backend/src/routes/lost-items.js`, `frontend/src/lib/api.js` (`deleteJson`), `frontend/src/app/broadcast/page.js`, `frontend/src/app/lost-items/page.js`
- **ทดสอบ:** curl ครบ 200 / 401 (ไม่ล็อกอิน) / 403 (role user) / 404 (ลบซ้ำ) / 409 (ของที่ส่งคืนแล้ว) และผู้ใช้ทดสอบในเบราว์เซอร์แล้วใช้งานได้ ข้อมูลทดสอบที่สร้างถูกลบทิ้งหมดแล้ว

## 4. ข้อมูลสถานที่รับของไม่ตรงกัน ✅

- **อาการ:** ดีไซน์ Nuxt ระบุ "SCB ชั้น 4" และเวลาทำการถึง 16:30 แต่หน้า `/contact` ของระบบระบุ "ชั้น 2 ห้องธุรการ" ถึง 16:00
- **วิธีแก้:** หน้าแรกใช้ข้อความเดียวกับ `/contact` (ฉบับที่ผู้ใช้แก้ให้ตรงของจริงแล้ว) ไม่นำข้อความจากดีไซน์ Nuxt มาใช้
- **ไฟล์:** `frontend/src/app/page.js`, `frontend/src/app/contact/page.js`

## 5. Lint เตือน `window.location` ในหน้า register ✅

- **อาการ:** `npx eslint src` เตือน `@next/next/no-location-assign-relative-destination` ที่ `register/page.js`
- **วิธีแก้:** สร้าง URL เต็มจาก `window.location.origin` ก่อนเรียก `assign` ตอนนี้ eslint ผ่านโดยไม่มีคำเตือน

## 6. หน้าอื่นที่ดึงข้อมูลผู้ใช้ใน `useEffect` อาจค้างสถานะเดิม ⚠️

- **ความเสี่ยง:** สาเหตุเดียวกับข้อ 1 หน้า `/dashboard`, `/lost-items`, `/returns`, `/admin/users`, `/account` ก็เก็บข้อมูลไว้ใน state ถ้าเปลี่ยนบัญชีโดยไม่โหลดหน้าใหม่ อาจเห็นข้อมูลของบัญชีก่อนหน้าชั่วคราว
- **ที่ทำแล้ว:** login/logout/register โหลดหน้าใหม่ทั้งหมด จึงครอบคลุมทางที่ผู้ใช้เปลี่ยนบัญชีตามปกติ
- **ยังไม่ได้ทำ:** ยังไม่ได้ลองเปลี่ยนบัญชีสลับหลายครั้งในทุกหน้า ถ้าพบอาการแบบเดิม ให้แจ้งหน้านั้นมา

## 7. ข้อความสถานที่/เวลารับของซ้ำ 2 ไฟล์ ⚠️

- `PICKUP_PLACE` และ `PICKUP_TIME` เขียนซ้ำใน `app/page.js` และ `app/contact/page.js` (ข้อความหน้าแรกย่อกว่าเล็กน้อย) ถ้าแก้ที่หนึ่งต้องแก้อีกที่ให้ตรงกัน
- ไม่ใช่บัค แค่ข้อควรระวัง ถ้าจะแก้ ควรย้ายไปไว้ไฟล์กลาง เช่น `src/lib/` แล้ว import ทั้งสองที่

## ข้อควรระวังจากดีไซน์ Nuxt (ไม่เอามาใช้)

ส่วนต่อไปนี้ใน `Design-outsourse/` ใช้กับระบบเราไม่ได้ จึงไม่ได้นำมา เพื่อกันไม่ให้ระบบพัง

- ใช้ role `student/admin` แต่ระบบเราใช้ `user/officer/admin`
- ส่งรูปเป็นลิงก์ แต่ระบบเราอัปโหลดไฟล์ (JPG/PNG/WebP ≤ 5 MB)
- ส่งสิทธิ์ผ่าน header `x-user-role` แต่ระบบเราใช้ JWT ใน cookie
- ใช้สถานะ `lost/returned` และหมวดหมู่ แต่ระบบเราใช้ `found/returned/disputed` และไม่มีคอลัมน์หมวดหมู่
- ฟอร์มส่งข้อความหน้า contact เป็นแค่ `setTimeout` ไม่มี backend
- ข้อมูลสมมติ: "98%", ดาวรีวิว, คำชมผู้ใช้, เบอร์โทร, อีเมลภาควิชา
- มีหน้า `forgotpassword.vue` ซึ่งขัดกับข้อตกลงที่ไม่ใช้ระบบลืมรหัสผ่านทางอีเมล
